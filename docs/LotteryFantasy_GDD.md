## 2. 문제 정의

[PROPOSAL] 복권/로또 테마의 모바일 게임은 단순 숫자 추첨 결과만 보여주어 재미(수집·성장·전략)가 부족하다고 가정한다.
- 파일명에 등장하는 덱(Deck), 배틀(Battle), 원소 에너지(ElementalEnergy) 시스템은 로또 추첨을 캐릭터 수집/전투와 결합하려는 의도로 추정된다.
- persona_playtest_feedback.md 파일이 별도로 존재하는 것으로 보아, 플레이테스트 피드백이 수집되어온 이력이 있으나 세부 내용은 미확인이다.

## 3. 한 줄 피치와 제품 포지셔닝

[PROPOSAL] 로터리 추첨을 판타지 속성 배틀과 덱 수집으로 이어주는 미니마켓(minimal)·캐주얼(casual) 모바일 게임.
- 포지셔닝: 기존 로또 앱과 판타지 카드 게임 사이의 하이브리드로 추정되나, 공식 포지셔닝 문서는 확인하지 못했다.

## 4. 주 페르소나

[PROPOSAL] 이서연(28세, 직장인, 출퇴근 지하철에서 5~10분 단위로 모바일 게임을 하는 문맥). 로터리 결과 건조함을 팔타지 진행으로 보완받고 싶어한다.
- 이 페르소나는 persona_playtest_feedback.md 본문을 확인하지 못한 상태에서 작성한 제안이며, 원문 대조 후 실제 이름/나이/직업으로 교체해야 한다.

## 5. 디자인 기둥과 핵심 재미

[PROPOSAL] 파일명 기준 추정 기둥: (1) 로터리 추첨 연동 수집(덱 구성), (2) 속성 기반 전투(원소 에너지), (3) 지속적 성장(배틀 반복).
- 핵심 재미는 '추첨 결과가 캐릭터 성장으로 이어지는 감각'일 것으로 추정되나, 이를 뒷받침하는 공식 설계 문서는 확인하지 못했다.

## 6. 핵심 루프

유저가 선택을 하면 결과가 되고, 그 결과 때문에 다시 선택을 한다.

[PROPOSAL, 정확한 순환 문장] 로터리 추첨 → 속성 매칭 분석 → 덱 구성 → 배틀 진행 → 보상 수령 → 로터리 추첨으로 돌아간다.
- 이 순환은 `DeckSystemTests.cs`와 `BattleManagerTests.cs`, `ElementalEnergySystemTests.cs` 테스트 대상 시스템명에서 역산한 구조이며, 실제 루프 설계 문서는 미확인이다.

## 7. 최초 30초 플레이 흐름

[PROPOSAL] 0-5초 로터리 추첨 연출 시청 → 5-15초 추첨 결과가 속성/캐릭터로 변환되는 배틀 준비 화면 → 15-25초 첫 배틀 턴 진행 → 25-30초 결과/보상 화면.

## 2026-09-21 출시 전 필수 재설계 — 사행성 리스크 (Unity 재개 전 선결 조건)

[FACT] 이 GDD 19절이 이미 "로터리 테마 모바일 게임은 지역별 사행법 규제 대상이 될 수 있다"고 자체 명시했다. 전체 포트폴리오 법무 리스크 감사(2026-09-21) 결과, 이 리스크가 이론적 우려가 아니라 **출시 자체를 막는 최상위 블로커**로 확정됐으므로 다음을 Unity 작업 재개 전 필수 선결 조건으로 못박는다.

- **문제의 핵심**: "추첨(로터리)" 결과가 곧 게임 진행(속성 매칭·덱 구성)과 보상으로 직결되는 구조는, 실제 화폐를 걸지 않아도 국내 게임산업진흥법·사행행위규제법상 "사행성 게임물"로 분류될 소지가 있다(우연적 방법으로 결과가 결정되고 그 결과에 따라 재산상 이익/손실에 준하는 진행상 이익이 좌우되는 구조).
- **재설계 방향(택1, Unity 재개 시 먼저 확정)**:
  1. "추첨"을 실제 확률형 뽑기가 아니라 플레이어가 사전에 확인 가능한 고정 패턴/스킬 요소(예: 타이밍 입력, 사전 공개된 카드 시퀀스)로 대체한다.
  2. 추첨 결과를 보상·진행과 완전히 분리하고, 연출(스토리 텍스트/비주얼)로만 소비되도록 재설계한다.
  3. 위 두 방향 모두 어렵다면 "로터리/추첨" 테마 자체를 폐기하고 속성 배틀+덱 수집 루프만 남긴다.
- 어느 방향을 택하든, 이미 구현된 "기본 확률·운 보정·릴 고정 비용·재추첨 확률 공개" 패널(2026-09-18 명세)은 사용자에게 확률을 투명하게 보여주는 장치일 뿐 사행성 분류 리스크 자체를 해소하지 못한다 — 완화 장치이지 해결책이 아니다.
- **플랫폼 판단**: 위 재설계가 확정되기 전까지 토스/구글플레이/스팀 어디에도 제출하지 않는다. 재설계 확정 후에는 구글 플레이스토어(모바일 캐주얼 세션, Unity Android 익스포트)를 잠정 1순위로 재검토한다.
- 이 항목은 Unity 미사용 정책에 따라 코드가 아닌 설계 문서로만 기록했다. Unity 작업 재개 시 가장 먼저 확정해야 할 항목이다.

## 2026-09-21 결과 후 라운드 흐름 피드백

- `SpinOutcomeAdvice.RoundFlow`를 추가해 결과가 다음 판단과 전투·보상으로 이어지는 위치를 한 줄로 표시한다.
- FIRE는 `추첨 완료 → 공격 판단 → 전투 → 보상`, IRON은 `추첨 완료 → 방어 판단 → 전투 → 보상`, LIFE는 `추첨 완료 → 회복 판단 → 전투 → 보상`, 혼합 결과는 `추첨 완료 → 보완 판단 → 전투 → 보상`을 사용한다.
- 기존 결과 헤드라인·에너지 합계·변화·다음 선택 아래에 흐름을 추가하며, 확률이나 보상을 변경하지 않는다.
- 목표 예시 화면: `docs/design-references/2026-09-21-round-flow-result-panel.png`.

### 검증과 제한

- 2026-09-21 독립 .NET 검증: FIRE·IRON·LIFE·Mixed 4/4 흐름 문구 통과.
- Unity EditMode 테스트에는 4개 흐름 단언과 `SlotMachineUI` 연결 검사를 추가했으나 Unity 미실행 정책으로 실행하지 않았다.
- Unity 빌드·씬·실기기 화면은 미검증이다.
- 본 변경은 결과 이해도 개선일 뿐 2026-09-21 사행성 리스크 블로커를 해결하지 않는다. 출시 제출 금지와 선결 재설계 조건은 유지한다.
